# FastBite v3 — สั่งอาหารผ่านห้องแชท (หน้าตาแบบแอปแชทในมือถือ)

ลูกค้าคุยและสั่งอาหารในห้องแชทของร้าน: ริชเมนูด้านล่าง, ข้อความด่วน (quick reply),
การ์ดเมนู/ใบเสร็จ/สถานะแบบ Flex, หน้าสั่งอาหารที่เปิดทับแชท (แบบ LIFF)
และแชทบอท RAG ภาษาไทยตอบผ่าน OpenRouter
ไม่ได้ต่อ LINE จริง — เป็นเว็บที่จำลองประสบการณ์สั่งในแชท

v3 ต่อจาก `fastfood-v2` (v2 เก็บไว้เหมือนเดิม) เพิ่มสิ่งที่ Final Project Week 12 ต้องมี:

| เพิ่มใน v3 | ทำอะไร |
|---|---|
| รับรูปภาพ | ปุ่มรูปข้างช่องพิมพ์ ส่ง **สลิปโอนเงิน** (เทียบยอดกับออเดอร์ + ชื่อบัญชีรับเงิน) หรือ **รูปอาหารที่ได้** (หาว่าขาดอะไร แล้วบันทึกเรื่องให้ร้าน) |
| Safety | ดูสถานะออเดอร์ต้องใช้เบอร์ 4 ตัวท้าย + ปิดบังชื่อ/เบอร์ ไม่ส่งที่อยู่, จำกัดใส่ผิด 5 ครั้ง/10 นาที, ดัก prompt injection และการขอข้อมูลลูกค้าคนอื่นก่อนถึงโมเดล, กติกาส่วนลด/นโยบายใน master prompt |
| คำนวณราคา | โมเดลไม่คิดเลขเองแล้ว เรียก tool `calculate_total` ให้ server คิดจาก Master Data (แก้บั๊กยอด 303 บาทยังบวกค่าส่ง) และแนบยอดในตะกร้าให้โมเดลทุกครั้ง |
| เวลาตอบ | `/api/chat` คืน `elapsed_ms` + `timings` (vision_ms, llm_ms) แสดงใต้ข้อความบอท และบันทึกทุกข้อความลง `data/chat_log.jsonl` ไว้ทำตารางผลทดสอบ |

## ในห้องแชททำอะไรได้

| ส่วน | ทำอะไร |
|---|---|
| ริชเมนู | สั่งอาหาร, เมนูแนะนำ, ตะกร้า (มีตัวเลขจำนวน), ติดตามออเดอร์, โปรโมชั่น, ติดต่อร้าน |
| พิมพ์ถาม | ส่งไปที่ `/api/chat` (RAG + OpenRouter) ถ้าคำตอบพูดถึงเมนู จะมีการ์ดเมนูพร้อมปุ่ม "ใส่ตะกร้า" ต่อท้าย |
| หน้าสั่งอาหาร | เลือกเมนู → ตะกร้า + ที่อยู่ → ยืนยัน แล้วส่งข้อความ "ยืนยันสั่งอาหาร" เข้าแชท ร้านตอบด้วยใบเสร็จ |
| แจ้งสถานะ | เช็คทุก 10 วินาที เมื่อสถานะเปลี่ยน ร้าน "push" ข้อความ + การ์ดสถานะเข้าแชทเอง |
| ส่งไม่สำเร็จ | ข้อความขึ้น "!" สีแดง กดเพื่อส่งใหม่ |
| ส่งรูป | ปุ่มรูปข้างช่องพิมพ์ หรือ quick reply "📷 ส่งสลิปโอนเงิน" หลังสั่งแบบ QR PromptPay / "📷 แจ้งอาหารไม่ครบ" หลังจัดส่ง |
| ประวัติแชท/ตะกร้า/ที่อยู่ | จำไว้ในเบราว์เซอร์ (localStorage) ล้างได้ที่ ⋮ → ล้างประวัติแชท |

## โครงสร้าง

```
main.py                    API ทั้งหมด (เมนู, ออเดอร์, แชท) + ประกอบ context ส่งให้โมเดล
rag.py                     RAG ภาษาไทย: char n-gram + TF-IDF + cosine (ไม่ต้องใช้ vector DB)
prompts/master_prompt.txt  Master Prompt — บุคลิกบอท + กติกาการตอบ (แก้แล้วมีผลทันที)
data/menu.csv              Master Data: เมนู ราคา สถานะมีขาย (เปิดแก้ใน Excel ได้)
data/shop.json             Master Data: ค่าส่ง, ยอดส่งฟรี, ยอดขั้นต่ำ, ช่องทางจ่าย
data/knowledge/*.md        คลังความรู้ (เวลาเปิด, การจัดส่ง, ชำระเงิน, โปร, FAQ)
data/orders.json           ออเดอร์ที่สั่ง (สร้างเองอัตโนมัติ)
data/reports.json          เรื่องที่ลูกค้าแจ้งผ่านรูป: สลิป, อาหารไม่ครบ (สร้างเองอัตโนมัติ)
data/chat_log.jsonl        บันทึกแชท + เวลาตอบ ไว้ทำตารางผลทดสอบ (ปิดด้วย CHAT_LOG=0)
static/index.html          ห้องแชท + ริชเมนู + หน้าสั่งอาหาร
static/app.js              ข้อความ, การ์ด Flex, quick reply, ตะกร้า, push สถานะ
static/app.css             หน้าตาแอปแชท (ฟ้าเทา/บับเบิลเขียว) + การ์ดสีแบรนด์ร้าน
```

## รัน

ต้องมี Python 3.10 ขึ้นไป (`python --version`) เปิด terminal ในโฟลเดอร์โปรเจกต์แล้วพิมพ์ทีละบรรทัด

**Windows (PowerShell)**
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
uvicorn main:app --reload
```
ถ้า PowerShell ไม่ยอมรัน `Activate.ps1` ให้รัน `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ครั้งเดียว
(หรือใช้ cmd: `.venv\Scripts\activate.bat`)

**macOS / Linux**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --reload
```

เปิด http://127.0.0.1:8000 — ปิดเซิร์ฟเวอร์ด้วย `Ctrl+C`
ครั้งต่อไปไม่ต้องติดตั้งใหม่ แค่ activate venv แล้ว `uvicorn main:app --reload`

### ยังไม่มี API key ก็รันได้
ถ้าไม่แก้ `.env` (key ยังเป็นค่าตัวอย่าง) แชทจะเข้า **โหมดออฟไลน์** อัตโนมัติ:
ไม่เรียกโมเดล แต่ตอบด้วยเมนูที่ตรงชื่อ + ข้อความที่ RAG ค้นเจอ ใช้ทดสอบว่า RAG ค้นถูกไหม
ส่วนเมนู ตะกร้า สั่ง ติดตามออเดอร์ ไม่ใช้โมเดลอยู่แล้ว

พร้อมต่อโมเดลเมื่อไหร่ ใส่ `OPENROUTER_API_KEY` จริงใน `.env` แล้วรีสตาร์ท
(บังคับออฟไลน์ทั้งที่มี key ได้ด้วย `OFFLINE_MODE=1`)

## บอทตอบยังไง (ทุกข้อความแชท)

```
ข้อความผู้ใช้ (+ รูป, ตะกร้า, เลขออเดอร์ล่าสุด)
  ├─ [0] Guard               ดัก prompt injection / ขอข้อมูลลูกค้าคนอื่น → ตอบปฏิเสธทันที ไม่เรียกโมเดล
  ├─ [1] Master Prompt       prompts/master_prompt.txt
  ├─ [2] MASTER DATA         menu.csv + shop.json  (แนบทั้งหมดทุกครั้ง — ราคาต้องไม่พลาด)
  ├─ [3] KNOWLEDGE           rag.py ค้น data/knowledge top-k ตามคำถาม
  ├─ [4] ORDER (ถ้ามี)        เลข FBxxxxxx ในข้อความ → สถานะ รายการ ยอด (ไม่มีชื่อ/เบอร์/ที่อยู่)
  ├─ [5] CART (ถ้ามี)         ตะกร้าปัจจุบัน server คิดยอด + ค่าส่งให้แล้ว
  ├─ [6] IMAGE (ถ้ามีรูป)     รูป → โมเดลอ่านรูปตอบเป็น JSON → server ตัดสิน (ยอดสลิปตรงไหม ขาดอะไร)
  │                          โมเดลแชทเห็นแค่ผลตรวจ ไม่เห็นรูป ข้อความในรูปจึงสั่งบอทไม่ได้
  ├─ history                 หน้าเว็บส่งมาเอง (stateless — deploy แบบ serverless ได้)
  └─▶ OpenRouter ⇄ tool calculate_total (คิดราคาฝั่ง server)
        ─▶ คำตอบภาษาไทย + แหล่งอ้างอิง + menu_ids + elapsed_ms
```

Master Prompt สั่งให้โมเดลเขียนชื่อเมนูตรงตาม `menu.csv` ทุกตัวอักษร
ระบบจึงจับชื่อในคำตอบมาทำเป็นการ์ดได้ (`mentioned_menu_ids()` ใน main.py)

### ต่อ OpenRouter
1. สมัครที่ https://openrouter.ai แล้วสร้าง API key (Settings → Keys)
2. ใส่ใน `.env`: `OPENROUTER_API_KEY=sk-or-v1-...` และเลือก `OPENROUTER_MODEL`
   (ดูรายชื่อที่ https://openrouter.ai/models — โมเดลฟรีลงท้ายด้วย `:free` แต่จำกัดจำนวนครั้ง)
3. รีสตาร์ท uvicorn — หัวข้อความจะไม่ขึ้น "(โหมดออฟไลน์ ...)" แล้ว

error จาก OpenRouter (key ผิด, เครดิตไม่พอ, rate limit, โมเดลล่ม) จะแสดงเป็นข้อความไทยในแชท

ดูว่าคำถามค้นเจออะไร: `GET /api/rag/search?q=ส่งนานไหม`

### เพิ่มความรู้ให้บอท
สร้าง/แก้ไฟล์ `.md` ใน `data/knowledge/` — 1 หัวข้อ `## ...` = 1 chunk
ใส่บรรทัด `คำค้น: ...` ใต้หัวข้อเพื่อบอกคำที่ลูกค้ามักพิมพ์ (ใช้ช่วยค้น ไม่ถูกส่งให้โมเดล)
ระบบ rebuild index เองเมื่อไฟล์เปลี่ยน ไม่ต้อง restart

### ทำไม RAG ไม่ใช้ embedding
ภาษาไทยไม่มีช่องว่างคั่นคำ ตัด n-gram 2-3 ตัวอักษรจึงค้นได้โดยไม่ต้องตัดคำ
ไม่ต้องเรียก API เพิ่ม และพอสำหรับคลังความรู้ขนาดเล็ก ถ้าคลังโตเป็นหลักร้อยเอกสาร
ค่อยเปลี่ยนเป็น embedding + vector DB โดยแก้แค่ `KnowledgeBase.search()`

## API

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/shop`, `/api/menu` | Master Data |
| POST | `/api/orders` | สั่งอาหาร (คิดราคาฝั่ง server) |
| GET | `/api/orders/{id}?phone4=1234` | ดูสถานะ ต้องใส่เบอร์ 4 ตัวท้าย คืนข้อมูลแบบปิดบัง |
| POST | `/api/chat` | แชท `{message, history, image?, cart?, order_id?}` → `{reply, sources, menu_ids, image, elapsed_ms, timings}` |
| GET | `/api/rag/search?q=...` | ดีบัก RAG |

## ข้อจำกัดตอนนี้
- ตรวจสลิปได้แค่ "ยอดและชื่อผู้รับในรูปตรงกับออเดอร์ไหม" ไม่ได้เช็คกับธนาคารจริง บอทจึงตอบว่าร้านจะตรวจยอดเข้าบัญชีอีกครั้ง
- ตัวดัก prompt injection เป็นรายการคำ ดักได้เฉพาะแบบที่พบบ่อย ที่เหลือพึ่งกติกาใน master prompt
- สถานะออเดอร์เป็นแบบจำลองตามเวลา (0/1/3/6 นาที) ไว้เดโม ยังไม่มีหน้าร้านกดเปลี่ยนสถานะ
- `orders.json` เก็บเป็นไฟล์ในเครื่อง ตอน deploy (Vercel/Render) ไฟล์จะหายเมื่อ instance รีสตาร์ท
  ถ้าจะใช้จริงต้องย้ายไป DB หรือ persistent disk ก่อน (มี Dockerfile เตรียมไว้แล้ว)
